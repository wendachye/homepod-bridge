# HomePod Bridge 0.12.5rc2

This beta candidate fixes echo between explicitly selected HomePods in the
Windows tray app. Both speakers now consume one live PCM source and share one
native AirPlay 2/PTP clock. The user confirmed synchronized playback in both
a shared-clock comparison and the complete Windows app on October 21, 2026.

Select both HomePod entries to play both speakers. Each retains its own volume
control. If a group transport fails, all members reconnect on a fresh common
timeline. A new two-receiver UDP test verifies matching audio payloads,
RTP timestamps and clock mappings.

Automated local checks passed: 235 Python tests, 986 native tests and the
packaged preview runtime smoke check. Four optional upstream native tests
remain ignored in the standard suite. Final versioned package and GitHub CI
results accompany the release assets.

## Install

Download **HomePodBridge.exe** from this release, quit the existing tray app,
and replace it with this executable. Keep your saved settings and select both
speaker entries. **Rescan**, then reconnect if startup discovery misses one.

The Python wheel is also provided, but does not bundle the native sender;
source installations must build that helper separately to use the group path.
Distributors of the Windows EXE must retain the accompanying native GPL
source archive, license and notices. If the source is split into parts, run
`Join-SourceArchive.ps1` beside all parts to reconstruct and verify it.

## Remaining validation and limitations

- This remains beta: overnight audible playback, network/speaker recovery,
  output changes, sleep/resume and clean-machine checks for the changed build
  are not all complete. Earlier validation is not claimed as a pass for this
  new implementation.
- Selecting one entry targets one speaker. Automatic playback of an entire
  Apple Home stereo pair from one selection is unsupported.
- CLI streams, mixed-device selections and installations without the helper
  use independent RAOP sessions and may still have offsets.
- Initial tray discovery can miss a selected peer. Rescan and reconnect when
  the selected count and connected count differ.
- Native playback has a live prebuffer plus receiver delay and is intended
  for music. `raop_latency` applies only to the pyatv transport.

See [the investigation](../sync-validation-2026-10-21.md) for the reproduction,
fix and exact preview evidence, and [release validation](../release-validation.md)
for the remaining hardware scenarios.
